name: code-rules
description: Use when implementing or refactoring TypeScript code in this Phaser project.
---

Работай по правилам проекта из `docs/ai/code_rules.md` и `docs/ai/layered-features.md`.

Ключевые правила:

1. Соблюдай слои:
   - `common`
   - `logic`
   - `services`
   - `assets`
   - `scenes`

2. Импорты разрешены только из более конкретного слоя в более абстрактный.

3. Внутри слоя импортируй только из своей фичи или из `shared`.

4. `shared` используй только если код реально нужен минимум двум фичам.

5. Типы и интерфейсы выноси в `types.ts`, кроме props, которые лежат рядом с компонентом, функцией или классом.

6. Если функция или конструктор принимает больше двух полей, используй props-объект с интерфейсом `I[name]Props`.

7. Константы для компонентов и сложных блоков выноси в `constants.ts`. Для маленьких файлов можно оставить рядом в начале файла.
   Если связанных констант больше одной, группируй их в объект `someNameConfig = { ... }`, а не в набор `SOME_CONST`.

8. Файлы для новых компонентов создавай в camelCase.

9. Не используй ссылочную типизацию вида `SomeType["field"]`, кроме разрешенного приведения внутри `switch case`.

10. Геттеры и сеттеры не добавляй по умолчанию.

11. Публичные методы располагай после конструктора и `destroy`, приватные - после публичных.

12. Для размеров и координат Phaser-объектов предпочитай `getBounds()`, когда нужны реальные видимые границы.

13. Интерактивность `Phaser.GameObjects.Container` делай через `makeContainerInteractive` из `common`.

14. При переносе файлов используй `git mv`.

15. Не импортируй Phaser, он доступен глобально.

16. Не запускай проверки без прямой просьбы пользователя.

Финальный ответ:
- что изменено
- какие файлы затронуты
- какие проверки не запускались
- какую проверку стоит запустить следующей
