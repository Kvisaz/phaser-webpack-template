## Когда использовать

Используй skill, если задача касается:
- визуальных эффектов
- particles
- floating text
- tween-анимаций
- money gain/spend effects
- burst/fly image effects
- cleanup активных анимаций
- pooling объектов эффектов

## Когда не использовать

Не используй skill для:
- обычной верстки UI без анимаций
- чистой игровой логики без визуального эффекта
- аудита ассетов без изменения эффекта
- сценового рефакторинга, где эффекты не затрагиваются

## Что открыть сначала

1. `docs/effects.md`
2. Связанный файл сцены или компонента, который вызывает эффект.
3. Если эффект общий:
   - `src/common/effects/**`
   - `src/common/animations/**`
4. Если эффект слушает scene events:
   - `src/scenes/shared/**`
   - `src/events`
5. Если эффект похож на денежный:
   - `src/scenes/shared/money-effects/**`

## Как выбрать место для кода

Добавляй код в `src/common/effects`, если эффект:
- не знает о конкретной сцене
- не знает о предметной логике
- принимает только scene/object/координаты/config
- может переиспользоваться в разных местах

Добавляй сценовый слой в `src/scenes/shared`, если эффект:
- слушает `IGameEvents`
- живет как контейнер сцены
- должен иметь общий depth
- обслуживает несколько UI/scene-модулей

Добавляй код рядом с фичей, если эффект:
- нужен только одной фиче
- зависит от ее локальных объектов
- не должен становиться shared

Не расширяй специализированные эффекты для несвязанных задач. Общие эффекты выноси в shared-слой отдельно.

## Порядок работы

1. Определи тип эффекта:
   - одноразовый tween
   - floating text
   - image burst
   - image fly
   - particle emitter
   - сценовый event-driven слой

2. Проверь, есть ли готовый примитив:
   - `FloatingTextEffect`
   - `ImageBurstEffect`
   - `ImageFlyEffect`
   - `ImageEffectPool`
   - `TextEffectPool`
   - `Anima`
   - `AnimaMover`

3. Если готовый примитив подходит, переиспользуй его.

4. Если нужен новый эффект, сделай минимальный модуль с props/config.

5. Если эффект создает много объектов, используй pool.

6. Для cleanup активных tween используй `killTweensOf`, если нужно снять tween без повторного `onComplete`.

7. Если эффект подписывается на events, используй `SceneEvents` и `autoUnSub`.

## Режим редактирования

Можно редактировать файлы, если пользователь просит реализовать или исправить эффект.

Только анализируй, если пользователь просит ревью, аудит или план.

Не меняй ассеты без прямой просьбы пользователя.

## Проверки

Не запускай typecheck, lint, build, браузер или dev server без прямой просьбы пользователя.

После изменения стоит предложить:
- `npm run typecheck`

## Готовый результат

Результат готов, если:
- эффект находится на правильном слое
- сцена не раздута логикой эффекта
- есть cleanup активных tween/подписок
- параметры вынесены в props/config, если их больше двух
- эффект не связан с чужой предметной логикой
- pooling использован там, где эффект массово создает объекты

## Формат ответа

Укажи:
- какой эффект добавлен или изменен
- где находится код
- какие существующие примитивы использованы
- как работает cleanup
- какие проверки не запускались
- какую проверку стоит запустить
