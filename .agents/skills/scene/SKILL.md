---
name: scene-work
description: Use when creating, refactoring, debugging, or reviewing Phaser scenes and scene components.
---

Работай со сценой как с местом сборки, а не как со складом логики.

Перед изменениями найди:

1. Основной Scene-класс.
2. Компоненты сцены.
3. Связанные assets-модули.
4. Логику из `src/logic`.
5. Сервисы из `src/services`.
6. События из `src/events` или локальных `events.ts`.

Правила:

1. Не раздувай Scene-класс.
2. Выноси повторяемую механику в компоненты, systems или services по текущей структуре.
3. Ключи ассетов не хардкодь глубоко в логике, если рядом уже есть config/constants.
4. Для Phaser input используй типизацию вроде `Phaser.Input.Events.POINTER_DOWN`.
5. Для размеров и координат используй `getBounds()`, когда нужны реальные видимые границы.
6. Не импортируй Phaser, он доступен глобально.
7. Не запускай браузер, dev server или проверки без прямой просьбы пользователя.

Финальный ответ:
- что изменено
- какие файлы затронуты
- какие проверки стоит запустить
