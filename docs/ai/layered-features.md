# Layered Feature Folders

Это руководство для проекта с нуля. Примеры ниже условные, они не привязаны к конкретной игре.

## Что такое слои
Слой — это уровень абстракции

Классический набор слоев (от самого абстрактного к самому “реальному”):
1) `common` — общее, не зависящее от игры.
2) `logic` — логика и типы игры.
3) `services` — сервисы игры (платежи, реклама, сохранения).
4) `assets` — UI-элементы, картинки, звуки, сборщики.
5) `scenes` — сборка экранов/сцен.

Правила импортов:
- Разрешены импорты только “вверх по слоям” (из более конкретного в более абстрактный).
- Нельзя импортировать “вниз по слоям”.
- Внутри слоя — только из своей фичи или `shared`.

Слои нужны, чтобы не путать ответственность и не тянуть зависимости “вниз”.

## Что такое фичи
Фича — это законченная область поведения игры: магазин, реклама, настройки, мини-режим, туториал.
Фича может иметь части в нескольких слоях: логика, сервисы, ассеты, сцена.

## Что такое shared
`shared` — это папка внутри каждого слоя для кода, который нужен нескольким фичам.
Примеры: общие UI‑кнопки в `assets/shared`, общие типы в `logic/shared`, общие утилиты в `common/shared`.

Важно:
- В `shared` кладём только то, что реально используется минимум двумя фичами.
- Если код нужен только одной фиче — держим его внутри её папки.

## Зачем их раскладывать
- Быстрее находить код фичи (меньше “скачков” по проекту).
- Проще переносить/удалять фичи без цепной реакции.
- Яснее границы ответственности, меньше конфликтов в git.

## Как раскладываем (с нуля)
1) Выбираем слои проекта.
2) Описываем список фич (любые, подходящие игре).
3) Внутри каждого слоя делаем папки фич и `shared`.
4) Складываем файлы фичи рядом в одном слое.
5) Оставляем сцену местом сборки, а не складом логики.
6) Реэкспортируем через `index.ts`.

## Минимальный пример (условный)

Фича “feature-a”:
- логика: `src/logic/feature-a/*`
- сервис: `src/services/feature-a/*`
- ассеты: `src/assets/feature-a/*`
- сцена: `src/scenes/MainScene/components/FeatureAOverlay/*`

Важно: это пример структуры, а не обязательное содержание.

## Правила импорта
- Не импортируем “вниз по слоям” (из `assets` в `services`, из `services` в `scenes`).
- Внутри слоя — импорт либо из своей фичи, либо из `shared`.
- Межфичевые связи — через фасад (например, центральный сервис) или `shared`.

## Плюсы
- Чище структура, меньше хаоса.
- Проще изолировать изменения.
- Проще переносить фичу целиком.

## Минусы
- Относительные импорты глубже.
- Возможность раздувания `shared`.
- Часть границ все равно пересекается в сценах.

## Рекомендации
- Перемещать фичи по одной.
- Использовать `git mv` для переносов.
- Не добавлять новый слой ради 1 файла (KISS).
- Держать фасады стабильными по публичному API.

## Сравнение с Feature Sliced Design
Feature Sliced Design (FSD) строится вокруг фич как главного уровня, и слой `features` часто становится центральным.
Layered Feature Folders оставляет слои первичными, а фичи — это лишь группировка внутри слоя.
Разница простая: FSD — “фичи сверху”, здесь — “слои сверху”.

## Более полный пример (условный)

```
src/
  common/
    utils/
    animations/
  logic/
    feature-a/
    feature-b/
    shared/
  services/
    feature-a/
    config/
    shared/
  assets/
    feature-b/
    shared/
  scenes/
    MainScene/
      components/
        overlays/
        ui/
        effects/
```

Пример показывает форму, а не “обязательный список фич”.
