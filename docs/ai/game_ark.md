# Архитектура игр на Phaser 3.90

Следуем этим концепциям

- viewBuilders - способ привязки входа конкретных ресурсов - графики, звуков - в игру
- компоненты - классы, инкапсулирующие визуальные части игры, используют viewBuilders
- эвенты - типизированная система `GameEvents` для связи компонентов и логики; используем camelCase события, описанные в `src/logic/events.ts`
- общий стейт - долгоживущие `State<T>` + краткоживущие `StateConnector<T>` для подписок UI/behaviorов
- Behaviors - подключаемые плагины сцены, работают через GameEvents и/или общий стейт

## ViewBuilders - вместо конкретных ассетов и ресурсов

Все игровые компоненты вместо конкретных ссылок на графику или звук должны использовать viewBuilders, которые передаются в аргументы конструктора.

Каждый вью-билдер - это простая функция без аргументов или с простым набором аргументов, нужных по контексту, для построения нужного визуального ресурса.

Примеры

```typescript
iconBuilder: () => Phaser.GameObjects.Image;
playSoundBuilder: ()=>void; // звуки воспроизводятся билдером без возврата
cardBuilder: (suit: string, value: number)=>Phaser.GameObjects.GameObject;
```

При создании нового компонента всегда проверь папку `src/assets/builders` на наличие подходящей фабрики билдеров. Если там ничего нет, а компонент надо где-то использовать. можешь создать в папке компонента подпапку builders c фабрикой временных билдеров на основе Phaser.GameObjects.Text (можно рисовать разноцветные прямоугольники с краткими текстовыми пометками), и используй их - позже я заменю.


## Компоненты

Все визуальные игровые элементы пишем как компоненты, складываем в папку components родительской папки. 

Компонент - всегда Phaser.GameObjects.GameObject. Для сложных компонентов используем Container.

Аргумент конструктора - всегда объект props с полями, даже если там используется один аргумент scene, для единообразия.

props в компоненте всегда объявляется как приватный элемент - для удобного и компактного доступа к его свойствам во всех методах.

Обязательное публичное и readonly поле - name - совпадает с названием компонента

```typescript
interface IProps {
  scene: Phaser.Scene;
  //... other fields
  text: string;
}

export class MyComponent extends Phaser.GameObjects.Container {
  // всегда пиши private props в конструкторе для экономии места!
  constructor(private props: IProps) {
    super(props.scene);
    const { scene, text } = props;
  }

  someMethod() {
    const { scene, text } = this.props; // деструктуризируем только необходимые поля
    //   операции с scene, text
  }
}
```

## эвенты

В `src/logic/events` находит описание общих эвентов для связи частей приложения в одно целое, а также класс для работы с такими эвентами.

## Общий стейт (State/StateConnector)

- Долгоживущие состояния храним в одном месте (`src/logic/state`), создаём `State<T>` и отдаём наружу функции для получения `StateConnector<T>`.
- Подписчики используют собственный `StateConnector`, чтобы убирать только свои подписки (`unSubScribeAll`) без влияния на других.
- Если `StateEvent.await()` ждёт обновления и вызывается `unSubScribeAll`, промис реджектится — учитывайте это при вызове.

## Верстка

Для верстки настоятельно рекомендуется использовать мнемонический [фреймворк Align](./layout.md) и другие полезные методы описанные по ссылке.
