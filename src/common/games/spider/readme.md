# Заметки по логике Паука

## Подсказка vs автоход

- Автоход (клик по карте) использует `findAutoMoveTargetTableau` с приоритетом целей.
- Подсказка использует `findHintMove`, который возвращает первый найденный валидный ход.
- Автоходов может быть несколько, а подсказка показывает только один вариант, поэтому полная синхронизация не гарантируется.

## Проблемы и решения

### Drag&drop: дроп по колонке "не ловится" и откатывается

Симптомы (по жалобам игроков):
- ручной дроп иногда "дрожит" и возвращается, хотя визуально игрок кладёт на валидную колонку;
- при нескольких одинаковых целях (например, 3 колонки с `5`) игроку важно выбрать конкретную, но вместо ручного дропа срабатывает автоход на "первую подходящую".

Причина:
- `DragDrop` выбирает `dropZone` по пересечению `getBounds()` перетаскиваемой карты и `getBounds()` зон.
- если у tableau `getBounds()` совпадает только с `cardPlace` (placeholder размером в одну карту), то при длинных колонках игрок часто дропает ниже placeholder, overlap = 0 и dropZone не находится.
- дальше срабатывает откат, а иногда действие распознаётся как клик → автоход.

Решение:
- расширяем bounds стопки tableau так, чтобы зона дропа соответствовала фактической высоте колонки:
  - объединяем bounds `cardPlace` и bounds `topCard`.
- реализация живёт в `SpiderStack.getBounds()` и не требует правок `DragDrop`.

См. также общий документ: `src/common/drag-drop/README.md`.
