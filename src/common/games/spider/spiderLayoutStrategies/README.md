# Spider layout strategies (tableau)

В этой папке лежат альтернативные стратегии раскладки **tableau** для игры Spider.

Цель: решить проблему супердлинных колонок, когда нижние карты могут уходить за пределы видимой области.
Стратегии **не меняют игровые правила и не трогают карты** (никаких flip/side/isFaceUp) — они меняют только вертикальные смещения (Y) при layout.

## Термины (как мы делим колонку)

Колонка tableau условно делится на 3 зоны:

1) `hidden` — закрытые карты вверху (back). В Spider они идут подряд.
2) `openButNotWorkTail` — открытые карты, которые *не входят* в переносимый хвост.
3) `workTail` — "рабочий хвост": максимальная убывающая по значению на 1 последовательность внизу колонки,
   полностью открытая (faceUp). Обычно это та часть, которую игрок реально перетаскивает.

## Доступные стратегии

### `mini` — маленький шаг для открытых карт вне хвоста

Экспорт: `spiderTableauMiniOffsetForNonTailLayoutStrategy`

Идея:
- `workTail` раскладываем нормальным шагом `workTailOffsetY` (читаемо и удобно для перетаскивания);
- `openButNotWorkTail` раскладываем маленьким шагом `collapsedOffsetY` (колонка растёт медленнее);
- `hidden` ограничиваем по высоте как в стандартном ограниченном layout: показываем только первые `maxHiddenOffsetCards` ступенек.

Когда выбирать:
- когда хочется, чтобы "масса" открытых карт всё ещё была видна ступеньками.

Минус:
- при очень большом количестве `openButNotWorkTail` высота всё равно растёт линейно.

### `limit` — лимитируем вклад открытых карт вне хвоста по высоте

Экспорт: `spiderTableauLimitNonTailCardsLayoutStrategy`

Идея:
- `workTail` как и в `mini` — нормальным шагом `workTailOffsetY`;
- `openButNotWorkTail`:
  - ступеньками показываем только последние `maxCollapsedOffsetCards`,
  - все более верхние открытые карты вне хвоста накладываем друг на друга (offset 0),
  - итоговая высота "нерабочей" открытой части ограничена.

Когда выбирать:
- когда бывают очень длинные колонки и `mini` всё ещё уезжает за экран.

Минус:
- часть открытых карт вне хвоста будет полностью перекрыта (но это именно нерабочая часть).

## Как включать (dev URL params)

По умолчанию (без параметров) включён режим `mini`.

- `?spiderTableauLayout=mini` — включить стратегию `mini`
- `?spiderTableauLayout=limit` — включить стратегию `limit`
- `?spiderTableauLayout=klondike` — включить старую стратегию (как было до экспериментов): `limitedHiddenCardLayoutStrategy`

Параметр читается в `src/scenes/SpiderGameScene/components/SpiderWrap/SpiderWrap.ts` и передаётся явно в `createDefaultSpiderStacksCreator`.

## Кейс: почему `mini` и `limit` могут выглядеть одинаково

Это ожидаемо в ряде ситуаций:

- В начале игры в tableau обычно есть закрытые карты и **ровно 1** открытая — зоны `openButNotWorkTail` фактически нет.
- Алгоритмы отличаются **только** в зоне `openButNotWorkTail`.
- Если открытых карт вне хвоста мало (например `<= maxCollapsedOffsetCards`, по умолчанию 8),
  то `limit` визуально почти совпадает с `mini`, потому что "оверфлоу" ещё не начался.

Чтобы увидеть заметную разницу:
- соберите колонку, где открытых карт вне хвоста много (например 15-30), и при этом есть переносимый хвост.
Тогда:
- `mini` даст длинную лесенку с маленьким шагом,
- `limit` схлопнет верхнюю часть и оставит по высоте только последние `maxCollapsedOffsetCards` ступенек + хвост.
