# AGENTS.md

## Базовый стиль

Пиши простой, чистый, модульный TypeScript-код. KISS и YAGNI важнее преждевременных абстракций.

Абстракции добавляй только когда они реально уменьшают сложность или совпадают с текущей архитектурой проекта.

По умолчанию используй именованные экспорты. Default export только если он уже принят в конкретном месте или явно нужен инструменту.

Для новых функций, методов и классов обязательны комментарии `/** ... */` на русском языке.

Комментарии `/** ... */` на русском языке обязательны для ключевых моментов кода, отвечающего за сложную верстку нескольких объектов, математические вычисления и сложные логические комбинации.

Window и его API считаются доступными.

## Проект

Phaser 3.90.0 / TypeScript 5.9.x.

Phaser подключен как статическая библиотека, импортировать Phaser не нужно.

Архитектура и правила проекта описаны в:
- `docs/ai/code_rules.md`
- `docs/ai/layered-features.md`

Важные файлы:
- `readme.md`
- `changelog.md` - обновляй только по просьбе пользователя
- `docs/effects.md`
- `docs/ai/task.md`
- `docs/ai/code_review.md`

Если документ противоречит реальному коду, сообщи пользователю и уточни, как поступить.

## Работа с файлами

Перемещение файлов и папок делай через `git mv`.

Не обновляй `changelog.md`, если пользователь не попросил.

## Проверки

Не запускай typecheck, lint, браузер или dev server без прямой просьбы пользователя.

Можно советовать запустить:
- `npm run typecheck`

## Skills

Используй skills из `.agents/skills`, когда задача совпадает с их описанием:
- `code-rules` - реализация или рефакторинг TypeScript-кода
- `event-bus` - события, `SceneEvents`, локальные `events.ts`
- `task-plan` - создание task-файлов и планов
- `code-review` - ревью кода
- `scene-work` - работа со сценами Phaser
- `effects` - эффекты, частицы, всплывающий текст
- `asset-audit` - проверка ассетов
- `finalize` - финальная проверка перед сдачей
